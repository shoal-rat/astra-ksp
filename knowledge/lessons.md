# Lessons learned in flight

Each line is one lesson from live flights: `- [date] (tags) lesson`. The first entries were harvested
from the previous ASTRA project's flight history (June 2026: Kerbin orbits, Mun landings and
returns, relays at the Mun, Duna, and Eve, crewed interplanetary attempts). They record how KSP 1.12.5,
kRPC 0.5.4, MechJeb 2.15, and the bridge plugin actually behaved. Numbers in them were observed on
specific craft: use them as evidence about the game, never as values to reuse. Search them with
`lessons_search`; add new ones with `lesson_add`.

- [2026-06-27] (infra, bridge) The bridge plugin loads only at KSP startup: a new or changed endpoint needs a rebuild, a DLL install into GameData/KspAutomationBridge/Plugins/, and a KSP restart. A stale DLL shows as "Unknown route" for an endpoint the source has; check the installed DLL's size and timestamp after each build.
- [2026-06-27] (infra, bridge) A running KSP memory-maps the plugin DLL, so overwriting it fails ("user-mapped section open"). Stage the build as a .new file and swap it in after KSP_x64 exits, keeping a .bak; KSP ignores .new/.bak files, but an older stale .new swapped in blindly downgrades the plugin.
- [2026-06-27] (infra, bridge) The only compiler that builds the bridge on this machine is the in-box .NET Framework csc v4.0.30319: C# 5 only (no string interpolation, ?., nameof, expression-bodied members). Under Git Bash use -flag not /flag, export MSYS2_ARG_CONV_EXCL='*' and MSYS_NO_PATHCONV=1, and pass absolute backslash paths.
- [2026-06-27] (infra, mechjeb) Compile the bridge against the installed MechJeb2.dll and MechJebLib.dll so a renamed MechJeb member becomes a compile error instead of a silently disabled feature (string reflection fails silently). MechJeb 2.15 dev names: core.Target (not core.target), EditableDouble.Val, the Users pool in PascalCase.
- [2026-06-27] (infra, mechjeb) Craft without an AR202 part carry no MechJebCore and every MechJeb call fails with "No MechJeb core". The ModuleManager patch MechJebForAll.cfg adds MechJebCore to every part with ModuleCommand; after a game reload it applies to saved vessels too.
- [2026-06-27] (infra) Start KSP with its install directory as the working directory (Steam app 220200), wait for the bridge and then for the main menu, then load the save. The bridge socket answers while KSP is still loading, and kRPC only serves once a save is loaded.
- [2026-06-27] (infra) The Windows console here uses the GBK code page: printing Δ, Ø, ✓ or emoji crashes or garbles output. Write files as UTF-8, pass encoding='utf-8' to subprocesses, and set PYTHONIOENCODING=utf-8.
- [2026-06-27] (infra) KSP runs localized as zh-cn although settings.cfg says en-us: part titles, biome names, module field/event GUI names, and recovery messages are Chinese, and launched vessels can get suffixes like '飞船'. Key parts on internal names, drive part modules by id (Module.fields also throws on duplicate GUI names), and match vessel names tolerantly.
- [2026-06-27] (infra, save) The default save folder on this install is named 默认, and KSP may be running a different save than the one configured. Craft files must go into the ACTIVE save's Ships/VAB (bridge /state saveFolder), or loading them 404s.
- [2026-06-27] (infra) The MS-Store Python cannot read files in AppData\Local\Temp; keep scratch files elsewhere (the repo's .scratch folder).
- [2026-06-27] (performance, save) A save with ~100 stray vessels (debris, failed transfers) made the game run ~3x slower than real time and confused vessel selection; pruning to ~36 vessels fixed it. When deleting VESSEL blocks from an .sfs, repoint activeVessel, which is a 0-based index.
- [2026-06-27] (bridge) The old bridge's JSON parser reads only string-valued fields: {"altitude": 80000} is silently ignored and the default is used. Send every field as a string ("80000", "false").
- [2026-06-27] (bridge) Non-ASCII request bodies hang the old bridge (it reads a byte Content-Length as characters): a UTF-8 body blocks until the client times out, and then the command runs anyway. Keep bridge request bodies ASCII until the parser is fixed.
- [2026-06-27] (bridge) A bridge 504 "Timed out waiting for Unity main thread" does not cancel the job: it stays queued and runs later. It means the game was paused, loading, or lagging. Check the game state (queue depth) before retrying, or a launch or load can happen twice.
- [2026-06-27] (bridge) The old bridge does not parse query strings (GET /state?x=1 is "Unknown route"); parameters go in a POST body.
- [2026-06-27] (bridge, save) /space-center and /fly-vessel overwrite the persistent save before changing scene, and /save only writes persistent: there is no rollback point unless a named save or quicksave was made first.
- [2026-06-27] (bridge) Old bridge vessel lookups (/vessel-info, /parts-list, /resources) match a substring over loaded vessels and silently fall back to the active vessel when nothing matches, returning ok with the wrong vessel's data. Check the returned vessel name.
- [2026-06-27] (bridge) The bridge writes NaN/Infinity doubles bare (e.g. apoapsis on an escape trajectory). Python's json accepts them; strict JSON parsers do not.
- [2026-06-27] (krpc) kRPC returns a new proxy object on every .part/.parent/.children access, so Python `is` and id() never match across calls. Compare with == (server object id). An id()-based part-tree walk crossed a decoupler and fired the payload separator on six crewed launches.
- [2026-06-27] (krpc, frames, attitude) AutoPilot.reference_frame must not rotate with the vessel: vessel.reference_frame raises "Invalid reference frame; must not rotate with the vessel". A swallowed exception meant ~13 docking attempts never pointed at all. Use body.non_rotating_reference_frame, vessel.orbital_reference_frame, the surface frames, or node.reference_frame. RCS translation (control.right/up/forward) is correctly in the vessel frame.
- [2026-06-27] (krpc, frames) vessel.flight() with no argument reads in a co-moving surface frame where speed and vertical_speed are ~0 for the whole ascent; a stuck-on-pad guard false-fired at 4 km. Read speeds with vessel.flight(body.reference_frame), and key liveness checks on apoapsis rather than one altitude sample.
- [2026-06-27] (krpc, attitude) Basic probe cores cannot hold SAS modes (setting sas_mode throws "Cannot set SAS mode"), and enabling SAS while the kRPC autopilot is engaged throws too. Point with the autopilot and re-target every tick to follow a moving vector such as retrograde.
- [2026-06-27] (krpc) This kRPC build names the orbital SAS speed mode SpeedMode.orbit, not orbital; resolve enum names defensively.
- [2026-06-27] (krpc, frames, burns) node.reference_frame has its y axis along the remaining burn, so an autopilot target of (0,1,0) in that frame tracks the burn as it proceeds. A direction captured once in the orbital frame drifts as that frame rotates.
- [2026-06-27] (krpc, burns) node.direction(), burn_vector() and remaining_burn_vector() can throw "Object reference not set" (null WorldBurnVector) for a node on a fresh post-escape patch. Rebuild the burn direction from the node's prograde/normal/radial components with prograde = v̂, normal = (r×v)̂, radial = prograde × normal in the body's non-rotating frame.
- [2026-06-27] (krpc) Adding maneuver nodes or editing their orbits requires the vessel to be the active vessel and in flight.
- [2026-06-27] (krpc) kRPC here runs with pauseServerWithGame=False, so RPCs, node edits, and telemetry reads keep working while the game is paused; that is what makes pause-while-thinking possible. Its settings.cfg once listed two identical default servers on the same ports.
- [2026-06-27] (krpc, transfer) After an ejection burn, orbit.body stays the origin body until the craft physically crosses the SOI boundary; a "body is the Sun" check made before the crossing silently skipped a whole mid-course phase. Wait for the SOI change before heliocentric targeting.
- [2026-06-27] (krpc) time_to_soi_change and next_orbit can be missing right after a burn or warp and appear a few seconds later. Let patched-conic predictions settle 2-4 s of game time before scoring a node or declaring a miss.
- [2026-06-27] (krpc, transfer) Orbit.distance_at_closest_approach is a single-conic estimate: near an SOI edge a predicted 38,737 km grazing encounter became a 3,866 Mm miss, and a predicted post-escape miss was off by ~900 Mm. Use node.orbit.next_orbit (body, periapsis) for encounters, and sample position_at in the Sun's non-rotating frame for miss distances.
- [2026-06-27] (krpc, burns, warp) vessel.thrust can read 0 for several seconds after leaving high rails warp while the engine is firing: a working capture read 0 thrust for 12 s while the apoapsis climbed 270 km. Confirm thrust by a semi-major-axis change or g_force before aborting a burn.
- [2026-06-27] (krpc, burns, warp) Engines were found deactivated after rails warp, and a 20 m/s burn shortfall lost a Duna encounter. Re-check engine state and available thrust after every warp.
- [2026-06-27] (krpc, staging) Aggregate vessel.resources misleads on staged craft: it showed 30% fuel while the active stage was dry and full stages sat below, and a burn was wrongly declared out of fuel. Read resources_in_decouple_stage(stage, cumulative=False) or per-part amounts, and stage into the fuelled element before calling a burn dry.
- [2026-06-27] (krpc, staging) resources_in_decouple_stage defaults to cumulative=True. The propellant of the burning stage s sits in resources_in_decouple_stage(s-1, cumulative=False).
- [2026-06-27] (krpc, burns) Integrate executed Δv as ∫(thrust·throttle/mass) over GAME time. Wall-clock integration under ~3x game lag cut an ejection short (a 3,774 Mm phasing miss); a velocity-difference measure over-burned a 1,020 m/s ejection by ~260 LF because the velocity rotates and the frame changes at the SOI.
- [2026-06-27] (krpc, transfer) A burn meant to reach a target apoapsis near escape must read next_orbit while still inside the origin SOI and the current orbit after crossing; reading an empty next_orbit after the crossing over-burned to a 75 Gm apoapsis.
- [2026-06-27] (krpc, chutes) Parachute state could not be read through kRPC on some craft; do not make parachute logic depend on the state readout alone.
- [2026-06-27] (krpc) Every scene change (launch, load, revert, space center) invalidates all remote objects and streams ("Instance not found"); flight-only procedures raise "Procedure not available in game scene". Re-acquire everything after a scene change.
- [2026-06-27] (krpc, staging, vessel-id) activate_next_stage, Decoupler.decouple and DockingPort.undock can change the active vessel; objects and streams built from the old vessel keep reporting it, and it may now be debris. Re-read the active vessel after every separation.
- [2026-06-27] (krpc) The Orbit API mixes time bases: position_at(ut), radius_at(ut) and true_anomaly_at_ut(ut) take absolute UT while orbital_speed_at(t) takes seconds from now. Engine *_at(pressure) methods take atmospheres while Flight.static_pressure is in Pascals. Orbit angles are radians; flight pitch/heading are degrees.
- [2026-06-27] (krpc, landing) Flight.mean_altitude, surface_altitude and bedrock_altitude are measured from the centre of mass, not the lowest point; subtract the CoM-to-bottom offset in touchdown math and use Leg.is_grounded as the contact signal.
- [2026-06-27] (krpc) kRPC's bounding box once returned degenerate ~1e18 m values in a bad frame; measure vessel length and diameter from part positions. Mass and part count were always reliable.
- [2026-06-27] (krpc) kRPC ties autopilot and control inputs to the client connection that set them, and closing a connection releases them. Throwaway extra connections opened mid-flight are a hazard; keep one persistent session.
- [2026-06-27] (krpc, performance) Every property read is an RPC round trip: the old code used no streams, its node searches made hundreds to ~4,750 add_node/remove calls, and a broad Mun-transfer brute force took >50 s of game time and missed its window. Stream telemetry, seed searches analytically, and keep them small.
- [2026-06-27] (krpc) sc.screenshot writes its file asynchronously after the frame renders and only in the flight scene; poll for the file with an absolute path.
- [2026-06-27] (warp) sc.warp_to(ut) blocks until the UT and never returns if the craft enters the atmosphere first, because KSP cancels rails warp at the edge. warp_to(periapsis) on a sub-atmosphere periapsis was the literal cause of a crew death. Cap every warp target at atmospheric entry or impact.
- [2026-06-27] (warp) Rails warp is capped by altitude: at 100 km around Kerbin factors above 3 (50x) are clamped, so a 1.77-year window wait would take ~90 real hours. High or heliocentric orbits allow 100,000x.
- [2026-06-27] (warp) Zero-fuel ways to wait for a window: wait on the ground before launch, or switch to a vessel in a high or solar orbit and warp there. Always stop warp before switching vessels: switching mid-warp can hang KSP.
- [2026-06-27] (warp, budget) Raising the apoapsis to warp faster and lowering it again for the ejection cost ~1,580 m/s (raise ~790 + lower ~790), not ~800, because the ejection then re-pays its full cost from the circular orbit.
- [2026-06-27] (warp, orbit) A high waiting orbit must stay clear of moon SOIs: Kerbin apoapses of 46,332 km and 9,902 km were perturbed or ejected by the Mun (orbit 12,000 km, SOI ~2,430 km), while ~6,900 km was clean.
- [2026-06-27] (warp) warp_to can hang on very near nodes, and a stepped rails warp polled every 0.5 s overshot a node by ~25 min because the ramp-down lags the poll; repeated bounded warp_to calls land precisely.
- [2026-06-27] (warp, burns) Under rails warp the throttle is ignored and engines cannot fire. A killed earlier run left a craft warping, and a "deorbit burn" produced no thrust, stranding a crew in a 62 km Duna circle. Zero rails and physics warp before any burn and verify thrust within seconds.
- [2026-06-27] (warp, reentry) No physics warp during powered ascent or the terminal landing phase, and no warp at all during a hot atmospheric entry: heating is applied in coarse steps under warp and two crews were destroyed that way.
- [2026-06-27] (warp, mechjeb) MechJeb's node executor will not autowarp to a distant node while it is still steering (steering caps warp): it sat in real time, a probe drained its battery in shadow (control state none, 179° pointing error), and it hung ~40 min from solar orbit. Warp to node minus ~45 s with MechJeb idle, then execute.
- [2026-06-27] (mechjeb, ascent) MechJeb's Classic ascent autopilot does not ignite the first stage from pre-launch; kick it once (throttle 1 plus one stage) and it flies the gravity turn and circularizes. PVG is meant for RSS/RO.
- [2026-06-27] (mechjeb, staging) Two stagers race: with MechJeb's ascent autostage on while decouplers were fired explicitly, MechJeb misread staging on fin and cluster geometry and lit an upper engine without firing the booster decoupler. Turn autostage off when you own staging; it must be set before the ascent autopilot is enabled.
- [2026-06-27] (mechjeb, staging, capture) MechJeb's StagingController is separate from the ascent autostage flag: the landing autopilot and an autostaging ascent leave it active, and it autostages during ANY later burn. It fired a heat-shield/payload decoupler mid-capture and stranded a crew pod at Eve with no engine, shield, or chutes. Release it before every in-space burn.
- [2026-06-27] (mechjeb, transfer) MechJeb's maneuver planner clears all existing maneuver nodes, plans from the current UT only, and fails with "No target set" unless the target is also set in MechJeb's core (SetVesselTarget alone is picked up a frame later).
- [2026-06-27] (mechjeb, interplanetary) MechJeb's interplanetary planner expects a low circular parking orbit: from a 6,900 km-apoapsis orbit it returned a retrograde, orbit-lowering node; from 100x2,500 km the ejection grew to ~1,400 m/s; from a clean 100-130 km orbit it gave a proper ~1,020-1,060 m/s Duna ejection.
- [2026-06-27] (mechjeb, interplanetary) MechJeb's transfer node produced a real encounter but its window was ~6 days off (a ~3,500 Mm phasing miss), while a Lambert porkchop matched to 0 km; a bare Lambert ejection without patched-conic refinement left 2.5-5.3x SOI misses. Use Lambert for timing, then close the loop against KSP's patched conics.
- [2026-06-27] (mechjeb, transfer) MechJeb's course-correction planner only refines an existing encounter; asked to create one from a heliocentric near-miss it diverged (338 -> 622 -> 1,502 m/s) and ran relays dry.
- [2026-06-27] (mechjeb, mun, transfer) MechJeb's planners ignore the Mun: a Kerbin ejection whose path crossed the Mun's SOI was deflected. Check the predicted patch chain for intermediate moon encounters before burning.
- [2026-06-27] (mechjeb, burns, interplanetary) Under heavy game lag MechJeb's node executor drifted ~2° off-axis over a 1,025 m/s ejection (heliocentric inclination 2.09° vs Duna's 0.06°, ~720 Mm out of plane); a manual burn aligned to <1.5° held 0.10°. Capping the throttle at 0.5 made it worse (gravity loss): big burns at full throttle.
- [2026-06-27] (mechjeb, burns) MechJeb's executor once left a close (~6 min) node unburned, while a hand-rolled executor ruined an encounter on a tiny normal-heavy correction that MechJeb flew precisely. Choose the executor per burn, and always verify the node was consumed and the orbit matches the prediction.
- [2026-06-27] (mechjeb, landing, reentry) MechJeb's landing autopilot owns deorbit, attitude, braking, and chute timing and beat every hand-rolled descent, but from a stable orbit above the atmosphere (a 62 km Duna circle) it never deorbited, and a held SAS retrograde fights it. Put the periapsis into the lower atmosphere yourself, release SAS, then engage.
- [2026-06-27] (mechjeb, reentry) MechJeb will not deorbit a craft whose periapsis is already inside the atmosphere but shallow: a 48 km Kerbin periapsis skipped out for hundreds of passes. Lower the periapsis into a real corridor at apoapsis first.
- [2026-06-27] (mechjeb, landing, warp) MechJeb's landing autopilot will not fast-warp a long descent ellipse from a high orbit (~9,400 km apoapsis); warp-assist down to near the top of the atmosphere, then hand control back.
- [2026-06-27] (mechjeb, docking, rendezvous) Docking: run MechJeb's rendezvous autopilot on the main engine first (it closed 1,078 -> 60 m), then the docking autopilot on RCS. The docking autopilot alone over km-scale gaps drained the monopropellant and stalled at "<0.00 m/s". Target the docking port, not the vessel, so it gets the axis.
- [2026-06-27] (mechjeb, docking) MechJeb's docking autopilot switches off on success, on target loss, and on the couple event, so "disabled" is not success; confirm with a part-count jump (21 -> 42) or a port state containing "Docked". The old /mj-dock picked the first non-docked port on both vessels (a stack-mounted pre-attached port counts as free) and left control-from-port set.
- [2026-06-27] (mechjeb, design) MechJeb's stage statistics (FuelFlowSimulation) give per-stage vacuum/atmospheric Δv, burn time, thrust, and TWR, matching rocket-equation burn times to ~1e-6 s; the first request is often empty (pending) and needs a second poll.
- [2026-06-27] (mechjeb) The old /mj-disable could not stop the ascent autopilot, the landing autopilot, or the node executor (only docking, rendezvous, staging); switching vessel or reloading was the only way to abort them.
- [2026-06-27] (mechjeb) MechJeb window planning needs a vessel with a MechJeb core; planning from a vessel without one failed.
- [2026-06-27] (staging, craft) A stack decoupler must share the inverse stage of the engines it exposes, so it fires as they ignite. Giving it the stage of the engines below split the craft on the pad; a launch stage with no decoupler above it dragged the whole stack and crossfed everything at sea-level Isp (88 km suborbital on 86% of the fuel).
- [2026-06-27] (staging) Tank-crossfeed transients can make an engine read dry for one poll, causing premature staging (the usual cause of a launch that "dies"). Require the dry state to persist before dropping a stage.
- [2026-06-27] (staging) Trigger a separation on the BOTTOM (deepest) active engine running dry, not on "all active engines dry": a wrongly lit upper hid a dead attached booster and left a relay at a 691 km apoapsis with both decouplers unfired.
- [2026-06-27] (staging) Never ignite engines by name or by lighting every engine that has fuel: it bypasses KSP's stage counter (a later activate_next_stage fired an already-spent stage), lit an upper against an attached booster ("heats the next tank, no speed gain"), and name matching lit only 1 of 5 engines when the pods used a different engine than the core.
- [2026-06-27] (staging) A decoupler is safe to fire only if some engine stays on the root/command side (walk each engine's parent chain with ==). Crewed stacks have two payload decouplers; a "the shallowest decoupler is the payload" heuristic fired the heat-shield one and jettisoned the whole 45-part upper stage.
- [2026-06-27] (staging) Never fire a decoupler whose lower side still holds significant propellant during end-of-ascent cleanup: it dropped a live transfer stage and stranded a Duna mission in low orbit.
- [2026-06-27] (staging) After a decouple, KSP splits the vessel over several physics frames: confirm the separation by a part-count drop before lighting the next engine.
- [2026-06-27] (staging, ascent) An oversized booster reached orbit still fuelled (a Mainsail with 923 LF left), so on-dry separation never fired and the upper dragged it through the next raise. Decide deliberately to drop spent-role stages at orbit insertion.
- [2026-06-27] (staging) Unthrottleable thrust (solid boosters, a copied SLS cargo craft) kept burning through a "coast" after throttle 0 and pushed the craft to escape. Measure actual thrust during coasts; if it persists, hold a safe attitude and watch for a non-finite time to apoapsis.
- [2026-06-27] (staging, craft) Radially attached cluster engines starved mid-ascent (thrust collapsed 2,526 -> 580 kN and the stack fell back); verify fuel flow to radial engines on the pad and in flight.
- [2026-06-27] (staging, craft) One generated craft put every payload-side stageable in stage 0 (all chutes, the heat shield, the capsule decoupler, the fairing, the lander decoupler), so a single stage activation would have fired all of them. Keep payload events in separate stages and read the stage table back after the craft loads.
- [2026-06-27] (ascent) Ascent failure signs, each held over consecutive samples: part count collapsing (breakup); apoapsis decaying below the atmosphere with negative vertical speed (falling back); landed or splashed after liftoff (crash); apoapsis decaying under power while far below target (diverging). Without these checks a dead ascent was watched for 20 minutes.
- [2026-06-27] (ascent, craft, attitude) Active control surfaces (AV-R8 winglets) under a weak probe-core autopilot over-rotated and tumbled a stack; four passive basic fins low on the booster gave a stable gravity turn.
- [2026-06-27] (ascent, craft) An exposed blunt payload (Mk1 pod + heat shield) raised the drag coefficient from 0.232 to 0.352 and the ascent drag loss from 286 to 433 m/s, so a 10 km/s vehicle fell back suborbital. It looked propulsive (two different upper engines "failed") but was aerodynamic; a fairing fixed it.
- [2026-06-27] (ascent, design) An estimated liftoff TWR of 1.24 never left the pad (apoapsis 89 m) because the estimate ignored ~0.5-0.8 t of accessories. Read TWR from the live loaded mass and sea-level available thrust before release.
- [2026-06-27] (ascent, design, burns) Heavy upper stages need a thrust floor: a 60 kN Terrier on a ~30 t upper (TWR ~0.2) crawled, lost Δv to gravity, and emptied the transfer stage having raised the apoapsis only to ~9,600 km. About 5 m/s² worked (a ~1,100 m/s burn in ~150 s); a Reliant upper at TWR ~1.1 twice failed to circularize a 237 t vehicle.
- [2026-06-27] (ascent, design) Moving a crew cabin above the capsule decoupler raised the centre of mass and the ascent stalled at ~39 km; a 574 t, 65 m, fineness-17 "needle" was unlaunchable. Radial boosters shorten the core and raise liftoff thrust.
- [2026-06-27] (attitude, design) Heavy upper stacks need inline reaction wheels: three 1.25 m wheels (~15 kN·m) took relay SOI arrival from ~50% to reliable. Hold energy-removal burns with the autopilot re-pointed every tick so the engine gimbal helps, not with reaction wheels alone.
- [2026-06-27] (attitude, burns) Wait for the pointing error to converge before igniting (up to ~2 min on a heavy stack) and abort rather than fire if it stays large; an unconverged ejection burned nearly retrograde and crashed a crew. "SAS on plus a fixed sleep" is not alignment.
- [2026-06-27] (attitude, burns) If the first seconds of a prograde burn lower the apoapsis, the burn is off-axis: cut, re-align, resume at low throttle so the gimbal can hold. Never flip the burn vector, and guard the parking periapsis. Short pulses on a craft with poor attitude response lowered an apoapsis that was meant to rise.
- [2026-06-27] (attitude, burns) The autopilot aligns the CONTROL part's forward axis, not the thrust axis: on one craft "retrograde" raised the periapsis, and on another the node's remaining Δv grew while both apsides fell. Check that the control part is aligned with the engines before burns.
- [2026-06-27] (attitude, craft) Surface-mounting a big reaction wheel on a small probe core clipped and destabilized the craft; mount wheels inline.
- [2026-06-27] (power) A probe with no electric charge cannot point (control state none, pointing error ~179°). Comsats spend part of every orbit in shadow, and solar output at Duna is ~43% of Kerbin's; carry an RTG and a large battery for deep space.
- [2026-06-27] (comms) CommNet link range is √(A·B) of the two antenna powers: an RA-2 with DSN level 3 gives 22.4 Gm, less than the 34.3 Gm Kerbin-Duna conjunction distance, so signal was lost. RA-100 with DSN3 gives 158 Gm; RA-100 to RA-100 gives 100 Gm. The Sun blocks the link regardless of power.
- [2026-06-27] (comms) Eccentric relay orbits bunch the satellites and open coverage gaps; a relay ring wants near-circular orbits with even spacing.
- [2026-06-27] (craft, comms) When the relay antenna part was missing from the part library, the old craft writer silently substituted a Communotron 16 and the relays lost signal at Duna. Check the actual antenna parts on the live vessel after launch.
- [2026-06-27] (orbit, bodies) Synchronous altitude is (μT²/4π²)^(1/3) − R and must lie inside the SOI: a Mun-stationary orbit is impossible (2,971 km altitude vs 2,430 km SOI); Kerbin's is 2,863 km, Duna's 2,880 km.
- [2026-06-27] (bodies, chutes) Duna's surface density read live is 0.133 kg/m³; an old catalog used 0.07 (a pressure value in atm), which made a single-chute Duna lander look survivable. Read densities live.
- [2026-06-27] (bodies) The old static body catalog had wrong rotation speeds (Duna 29.36 vs 30.69 m/s, Ike 18.6 vs 12.47 m/s) and silently fell back to Kerbin for unknown names. Read body constants live.
- [2026-06-27] (bodies, design) Eve's ~6.2 kg/m³ surface air (~5 atm) makes a surface ascent cost ~8,000 m/s, so an Eve surface round trip was judged infeasible; Gilly from a low Eve orbit cost ~2,480 m/s round trip, dominated by the transfer to its 31,500 km orbit.
- [2026-06-27] (design, bodies) Vacuum engines keep only ~23-26% of their vacuum thrust at 1 atm (Terrier, Nerv, Poodle) while sea-level engines keep 85-94% (Reliant, Mainsail, Vector). Evaluate thrust and Isp at the actual ambient pressure; Eve's ~5 atm makes 1-atm figures badly optimistic.
- [2026-06-27] (mun, transfer) Seed a Mun transfer from the Hohmann phase angle and refine with a small patched-conic search, widening to about three orbits only if no encounter appears; a brute-force search over 10,000 live nodes took >50 s and missed the window.
